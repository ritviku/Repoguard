What RepoGuard does

Finds exposed API keys, tokens, passwords and private keys committed to a repository.

npm audit · pip-audit

Dependency vulnerability audit

Checks third-party packages against known CVE databases so outdated, vulnerable libraries are flagged before they ship.

Report

Filterable findings

Read-only

Safe by design

Uses a shallow, read-only copy of a public repository. Nothing is executed and nothing is attacked.

Established scanners do the detection

Detection is done by well-known, deterministic tools, so results are repeatable and not an AI guess. The AI only explains and prioritizes what those tools found.

The AI reads findings, not your code

The model receives a short, structured list of findings rather than the whole repository. That keeps cost low, keeps the report focused, and limits how much of your source is ever sent to a model.

Built for the people who skip security reviews

Small teams and solo developers rarely have time for a full audit. RepoGuard gives them a prioritized report in one step, with fixes they can apply the same day.

Honest about its scope

This is automated static analysis (secret detection and dependency scanning), not a penetration test. We say so in the product, along with its known limitations, because trust in a security tool starts with accurate claims.

What this checks

RepoGuard runs two categories of automated static analysis: secret detection (via gitleaks) and software composition analysis (via npm audit / pip-audit) against known CVE databases. It does not execute the application or attempt exploitation — this is not a penetration test.

Why AI is used

The scanners above do all the detection work, deterministically and for free. The one AI call reasons over a short, structured list of findings — not the raw repository — to rank severity, explain risk in plain language, and suggest fixes. That is why this uses a small fraction of the tokens an approach that asked an AI to read the whole repository would need.

Known limitations

Secret detection carries known false-positive and false-negative tradeoffs inherent to the underlying tool. This prototype does not check GitHub Actions configuration, repository settings, or source code patterns beyond dependency and secret scanning. It does not replace a professional security audit.
